# 2026-08-20

## SignalTap — e2e suite greened + discussion extraction fix

Final blocker resolved: Playwright e2e (`apps/extension/tests/e2e`) now passes
both article + discussion specs. Root causes found while debugging:

1. **Discussion comments not extracted.** `GenericArticleAdapter` / `GenericVisibleTextAdapter`
   hardcoded `discussionItems: []`. Added `extractDiscussionItems(doc)` in `src/adapters/dom.ts`
   (comment-root + author/score/permalink detection) and wired into both generic adapters.
   Now the mock provider derives `consensus` / `disagreements` / `bestComments` from real comments.

2. **Cache miss after reopening the panel (real product bug).** `highlightSource` appended a
   `<span class="sigsoil-label">SignalTap source</span>` *inside* the highlighted element. On
   re-extraction `cleanText(el.textContent)` picked up that string → extraction fingerprint
   changed → cache key drifted → no cache hit (and it pollutes real analysis too).
   Fix: render the label via `.sigsoil-label::before { content: attr(data-label) }` so it is
   NOT part of `textContent`.

3. **Cache-write race.** `putCached` ran *after* `setPhase("done")`; a panel close the moment
   the result rendered could abandon the in-flight `chrome.storage.local.set`. Moved the write
   before `setPhase("done")`.

4. **Test/launch fixes.** `helpers.ts`: read active tab `.id` (no `tabs` permission needed);
   patch localhost `host_permissions` into the *test* build only (shipped manifest stays
   activeTab-only). E2E locators switched from loose `text=Signal` to precise `.st-section-title`.
   Removed redundant dynamic import of `deleteRemoteAnalysis` (killed Vite warning).

Verification: `npm run typecheck` clean; unit tests 47/47 (backend 9 + extension 38);
e2e 2/2. Committed `55d02cb` and pushed to `git@github.com:Shmily0826/SignalTap.git` (main).
Removed stray `diag-launch.mjs` debug file.

Lesson: on this Windows box, stray `chrome.exe` processes from crashed debug scripts cause
`launchPersistentContext` to silently fail — always `taskkill /F /IM chrome.exe` before e2e.

## Long-content strategy implemented

Spec required a long-content strategy; there was previously zero truncation anywhere, so a
very long page would blow the LLM context. Added:

- `packages/analysis/src/truncate.ts` — pure `truncateExtracted(e, limits?)`:
  - main content capped by `maxBlocks` (keep document order) then `maxChars` (keep whole blocks,
    trim the single overflowing block rather than dropping a section);
  - discussion items capped by `maxComments` (keep top-scored, then re-sort by document position);
  - every reduction reported via `extractionWarnings` (`content_truncated` / `comments_truncated`);
  - source IDs of kept items untouched → click-to-highlight still resolves; never invents/reorders.
  - Defaults: maxChars 24000, maxBlocks 120, maxComments 60 (overridable via env MAX_CONTENT_CHARS /
    MAX_CONTENT_BLOCKS / MAX_COMMENTS in the backend).
- Backend `runAnalysis` now truncates `req.extracted` (via `TRUNCATE_LIMITS`) before both the
  primary and mock-fallback providers, so stats reflect what was actually analyzed.
- New tests `apps/backend/tests/truncate.test.ts`: 7 cases (no-op under limits, block cap, char
  budget, no input mutation, comment top-score cap + order, runAnalysis subset). Backend suite
  now 16/16. Full green: typecheck clean, ext 38/38, backend 16/16, e2e 2/2.

Note: `@signaltap/analysis` resolves from `src/index.ts` (exports map), backend runs via `tsx`,
tests via vitest alias → source-of-truth, no separate package build needed when adding modules.
